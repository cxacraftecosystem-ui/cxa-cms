# CxA Portal — build contract

**Read this before writing any file in this repository.** It is the contract, not a summary. Every
rule below has a reason after it, and most of those reasons are a bug that shipped once in the
sibling product (`D:\Portal_Development_Web`, whose design system this inherits verbatim).

The authoritative upstream reference is
`D:\Portal_Development_Web\.claude\skills\field-repo-frontend\SKILL.md`. Where this file and that
one differ, **this file wins for this repository** — the two divergences are listed in §1.

---

## 0. What this product is

The public digital presence of a Centre of Excellence — institutional identity, research showcase,
knowledge portal, media centre, recruitment portal and living archive — with an **invisible CMS**
behind it. Two audiences, two completely different experiences:

| Surface | Route group | Feel |
|---|---|---|
| Public site | `app/(site)/**` | Cinematic. Depth, motion that means something, huge whitespace. |
| Studio (CMS) | `app/studio/**` | Calm, dense, obvious. As simple as editing a presentation. |

**No visible link ever points from the public site to the studio.** The studio is reached by typing
`/studio` or `/console`, by `Ctrl+Shift+A`, or by clicking the footer wordmark seven times.

## 1. Non-negotiables

1. **Purple-700 `oklch(0.47 0.198 305)` is the only action colour.** No second accent on a studio
   screen, ever. Gold is marketing-only (hero, section eyebrows on the public site), ≤5% of a
   viewport, and never on a studio screen.
2. **Never hardcode a neutral.** Every grey goes through the themed `ink-*` / `line-200` /
   `surface-*` / `bg-0` / `card` ladders, which invert under `data-theme="dark"`.
3. **Reduced motion needs BOTH paths.** CSS covers CSS; framer-motion writes inline styles and needs
   a JS branch — `useReducedMotionPreference()` from `components/motion/`. A framer animation with no
   JS branch still animates for a reader who asked it not to.
4. **A signal that only exists as motion is a signal reduced-motion readers never get.** Pair every
   pulse with a static state (a ring, a border, a word).
5. **Never invent a z-index.** Pick from the ladder in §6.
6. **Truncation, caps and skipped work must be stated on screen.** A list that quietly stops is
   indistinguishable from a place with no records — the single most repeated bug class upstream.
7. **A client guard that only hides a control is not a guard.** Every gated action checks the same
   predicate from `lib/permissions.ts` on the client *and* in the route handler.
8. **A failing permission check renders NOTHING, never a disabled control.** An ungated button that
   lands on a refusal invites every tier to press it.
9. **Guard a PAGE with `requireStudioCapability` / `requireStudioRole`; guard a ROUTE HANDLER with
   `requireCapability` / `requireRole`.** They are not interchangeable. The handler pair throws an
   `ApiError` that `route()` turns into a 403 JSON body. The page pair calls Next's `forbidden()`,
   which renders `app/forbidden.tsx` with a real 403 status. Using the handler pair inside a Server
   Component produces an unhandled throw, a **500**, and a screen telling an editor "something went
   wrong on our side" — which is false, and sends somebody hunting a fault that does not exist.
   `error.tsx` cannot repair it: Next redacts a server error's message in production, so the boundary
   cannot tell a deliberate refusal from a genuine fault. This shipped once, on four screens.

**The two deliberate divergences from the upstream skill**, both strictly additive:

- `bg-surface-100/200/300` **do compile here** (upstream only declares `surface: { 50 }`). The legacy
  `bg-field-100/200/300` aliases still work; prefer the real names in new code.
- Brand amber is also exposed as `warn-100/500/800`, so a component can avoid the deep-merge with
  stock Tailwind amber. `amber-100/500/800` are retained; **`amber-50` and `amber-200` are stock
  Tailwind and will not pair correctly** — inside a tinted card use `amber-100` + `amber-800`.

## 2. Type

**Local** variable faces in `fonts/`, loaded by `next/font/local` in `app/layout.tsx`.
**Never load Google-hosted fonts.**

**`lib/typography/fonts.ts` is the register of faces** — generated by `npx tsx scripts/fetch-fonts.ts`
and never edited by hand. It is the ONE place a face is described, so a face cannot be offered under
two names or two descriptions. Read it (or `facesByRole()`) rather than hardcoding a list.

These four slots are the site's default voice and are unchanged:

| Slot | Variable | Face | Weights |
|---|---|---|---|
| `font-sans` | `--font-inter` | Inter — body/UI | 100–900 |
| `font-display` | `--font-jakarta` | Plus Jakarta Sans — headings | 200–800 |
| `font-serif` | — | **alias of `font-display`** — NOT a serif | — |
| `font-mono` | — | **undefined** — resolves to the system monospace | — |

Everything else in the library is an **additive key**: ten further families (six serifs including
Source Serif 4, Lora, Crimson Pro, Newsreader, Fraunces and Playfair Display; Work Sans and Figtree;
Archivo Narrow; JetBrains Mono), ten of the twelve with a **true drawn italic**. Nothing was repointed.
`font-jetbrains-mono` is the real monospace; `font-mono` is still the system stack.

⚠ **Emit `face.fontClass` verbatim. Never build `` `font-${key}` ``** — a class assembled at run time
never appears in the source Tailwind scans, is purged, and silently does nothing (§5).

⚠ **Offer only `weightsFor(face)`.** A variable font clamps an out-of-axis weight silently, so
`font-black` on a 400–700 face renders at bold and the control looks broken.

⚠ **`preload` on `next/font/local` defaults to TRUE.** Omitting it on a face declared in the root
layout puts a high-priority preload in the head of *every* route. Only Inter and Jakarta are preloaded,
because every page is set in them; every added face is `preload: false` and is fetched by the browser
only when a glyph is actually painted with it. Declaring a CSS variable costs a few bytes and fetches
nothing — which is what makes 880 KB on disk cost nothing per page.

⚠ **A face's licence must ship with its files.** OFL-1.1 §2 permits redistribution "provided that each
copy contains the above copyright notice and this license" — a *name and a URL in the manifest is not
that*. The texts live in `fonts/licences/`, one per face plus an index. `npm run font-check` fails if
one is missing, truncated, or is not the licence it claims to be, and also verifies every declared file
exists, hashes as recorded, and is declared in `app/layout.tsx` and `tailwind.config.ts`. This is
distinct from the CC BY photographs, whose licence obliges attribution to the **reader** and which are
credited on `/credits`.

`fontSize`, `spacing`, `screens`, `letterSpacing` and `zIndex` are **stock Tailwind**. Breakpoints
are stock: `sm` 640 · `md` 768 · `lg` 1024 · `xl` 1280 · `2xl` 1536.

## 3. Colour traps

- **`className="border"` alone** gives preflight's literal `#e5e7eb` (gray-200), which does not
  invert. Always `border border-line-200`.
- **`ring-2` / `ring-4` alone** uses preflight's **blue** `rgb(59 130 246 / 0.5)`. Always name the
  colour: `ring-purple-600/15`, `ring-offset-card`.
- **The `field` scale is shifted by one stop, so the name lies:** `field-500` → purple-**600**,
  `field-600` → purple-**700** (the action colour), `field-700` → purple-**800**. Prefer real names.
- **Status colours are literal hex and do NOT invert:** `warn/amber-100/500/800`,
  `success-100/600`, `error-100/200/600/700`. This is on purpose — a status must read the same in
  both themes. `success-500` does not exist.

## 4. Radius, shadow, easing

**Radius overrides stock:** `rounded-sm` 8px · `rounded-md` 12px · `rounded-lg` 16px ·
`rounded-xl` 24px. **Not** overridden: `rounded` = 4px (**tighter than `sm`**), `rounded-2xl` = 1rem
(**numerically identical to `lg`**), `rounded-3xl` 1.5rem, `rounded-full`. *Reading a class name is
not enough to know the visual radius.*

**Shadows are all purple-tinted:** `shadow-sm`/`soft`, `shadow-md`, `shadow-lg`/`panel`,
`shadow-island`, `shadow-cta`/`glow`, `shadow-glow-soft`, `shadow-cinema`.
**`shadow`, `shadow-xl`, `shadow-2xl`, `shadow-inner` are stock black — do not use them.**

**Easing.** `ease-out` the *class* is redefined to the brand expo curve
`cubic-bezier(0.16, 1, 0.3, 1)`; `ease-spring` = `cubic-bezier(0.34, 1.56, 0.64, 1)`.
⚠ The literal keyword `ease-out` **inside handwritten CSS** is the CSS spec curve, not this one —
the two look identical in source and are different curves.

**Gradients — exactly three recipes:** `.grad-brand`, `.grad-mesh` (alias `.ambient-light`),
`.text-gold-gradient`. Do not invent a fourth.

## 5. `cn()` is a plain join

`lib/utils.ts`'s `cn()` is `classes.filter(Boolean).join(" ")` — **not** `tailwind-merge`, and
neither `clsx` nor `tailwind-merge` is a dependency. This matches upstream deliberately so components
can be copied between the two products.

**Consequence: later classes do NOT win.** CSS source order decides. A `@layer components` recipe is
always beaten by any utility (so `className="field-button w-full"` works), but to beat another
*utility* you need `!` — e.g. `!bg-transparent`.

⚠ **Content globs are `./app`, `./components`, `./lib` only.** A class written elsewhere, or built by
string concatenation, is purged. **Always write complete literal class strings.**

⚠ `postcss.config.js` loads only `tailwindcss` + `autoprefixer` — **no nesting plugin.** Arbitrary
CSS nesting in `globals.css` will not compile; `@layer` blocks and plain at-rules do.

## 6. The z-index ladder — pick from it, never invent

| z | What |
|---|---|
| 10 | sticky in-page chrome (table heads, studio toolbars) |
| 40 | bottom docks, the nav scrim |
| 50 | the site header / studio top bar — page chrome must not exceed it |
| 60 | skip link |
| 70 | popovers portalled to `<body>` |
| 100 | dialogs |
| 105–108 | stacked dialogs (a confirm opened from inside a dialog) |
| 110 | toast viewport |

Anything `position: fixed` and horizontally centred must also carry
`padding-right: calc(<its own> + var(--scroll-gutter, 0px))` — the scroll lock takes the scrollbar
away and fixed chrome cannot inherit the body padding that pays it back. Use `.nav-frame` /
`.overlay-frame` from `globals.css`.

## 8. The motion vocabulary

All of it lives in `components/motion/`. **Do not invent spring numbers.**

| Spring | Value | Job |
|---|---|---|
| `SPRING_ISLAND` | `{ stiffness: 260, damping: 30 }` | header layout, sheet slide |
| `SPRING_PRESS` | `{ stiffness: 380, damping: 30, mass: 0.7 }` | every press/hover response |
| `SPRING_LAYOUT` | `{ stiffness: 260, damping: 32, mass: 0.9 }` | layout changes, accordion height |
| `SPRING_SCROLL` | `{ stiffness: 140, damping: 30, mass: 0.4 }` | scroll-linked spines |
| `SPRING_POINTER` | `{ stiffness: 110, damping: 24, mass: 0.6 }` | hero pointer wash |
| `SPRING_POPOVER` | `{ stiffness: 520, damping: 38, mass: 0.6 }` | popovers |
| `SPRING_TOAST` | `{ stiffness: 420, damping: 34, mass: 0.7 }` | toasts |

`EASE_OUT = [0.16, 1, 0.3, 1]` — the house cubic, identical to the `ease-out` token.
Durations in use: `0.18s` (scrim, opacity) · `0.22s` (width, page fade) · `0.28s` in / `0.16s` out
(swap readouts) · `0.4s` slide · `0.5s` rise · `0.62s` GSAP words.
Staggers in use: `0.08` · `0.06` (default) · `0.05` · `0.045` · `0.04` · `0.035` · `0.025`.

**Reduced motion, in JS.** `useReducedMotionPreference()` unions framer's `useReducedMotion()` (the
OS half) with the `data-reduced-motion` attribute (the in-app half), watching it with a
`MutationObserver` so flipping the toggle takes effect without a reload.

- **Gate at the source.** Every factory in `components/motion/variants.ts` takes `reduce` and
  collapses to zero duration *and* zero displacement.
- **On the public site, reduced motion changes DURATIONS, never the `initial` state.** An `initial`
  that branches on a value which is false during SSR and true after hydration produces a flash.
  (Inside the studio, where nothing is prerendered for anonymous readers, branching `initial` is
  fine.) Do not copy either pattern across.
- **Never centre a framer-animated element with a translate class** — framer writes an inline
  `transform` and the class loses. Centre with margins.
- Ornaments are `aria-hidden`. **No `aria-live` on a scroll-position readout** — it would interrupt a
  screen-reader user on every scroll for information they already have.

**GSAP owns two things, and the line between them and framer is ENTRANCE versus SCRUB.**

1. **A timeline whose tweens deliberately overlap** — the homepage headline's per-word reveal, where
   each word starts *while the previous is still moving* (an offset measured from a sibling's START,
   which is a timeline primitive framer's `staggerChildren` cannot express).
2. **Scroll-scrubbed motion** — parallax, a pinned rail, a path that draws itself as the reader
   descends, a figure that holds while its chapter passes. This is what the four narrative blocks
   (STORY_SCROLL, PARALLAX_BANNER, HORIZONTAL_RAIL, PROCESS_STEPS) use, through
   `components/motion/gsap/useGsapScope.ts`.

**Everything else is framer's, including every entrance.** Reaching for GSAP to make a section fade
up means two animation systems where one would do.

⚠ **THE INVARIANT THAT MAKES SCRUBBED MOTION SAFE: every element GSAP touches is already in its
final, readable position in the HTML.** A parallax layer at rest is the layer; a sticky figure with
no JavaScript is a sticky figure. So there is no `opacity: 0` initial state to rescue, no `<noscript>`
rule to write, and no flash if the chunk never arrives — the page is simply the page, and reduced
motion builds nothing at all. **A new GSAP animation that needs something hidden until JavaScript
runs is a `Reveal` that has been written in the wrong library.**

⚠ **Never let both libraries touch the same property on the same element.** They each write
`transform` on their own schedule and the result is jitter that reads as a rendering bug. GSAP owns
the headline's word spans and the narrative blocks' scrubbed layers; framer owns everything else.

Both are loaded by **dynamic `import()`** — GSAP plus ScrollTrigger is ~95 KB and must not sit in
every page's bundle. `components/motion/gsap/runtime.ts` memoises that import, registers the plugin
once, bridges Lenis to `ScrollTrigger.update` so scrubbed layers do not trail the page by a frame,
and refreshes trigger positions when a late image or font swap changes the document height. Every
trigger is created inside `gsap.context()` and reverted on unmount — an orphaned ScrollTrigger keeps
recalculating against elements that have left the document.

**Lenis** provides the smooth-scroll feel on `(site)` routes only. It must be disabled entirely under
reduced motion, and it must never be mounted inside the studio (a CMS that scrolls with inertia feels
broken when you are trying to hit a row).

## 9. Data and API conventions

- **`lib/api.ts` is the only error vocabulary.** Throw `ApiError` / `unauthorized()` / `forbidden()` /
  `notFound()` / `conflict()` / `badRequest()`; wrap every handler in `route()`. The body shape is
  `{ error: true, message, code, fieldErrors? }` and `message` is **always a plain human sentence
  ready to render verbatim** — upstream printed `"[object Object]"` to users for months because it
  was not.
- **Validate every input with Zod** through `parseJson` / `parseQuery`. Never trust a body shape.
- **Call `assertSameOrigin(request)` first in every mutating handler.**
- **Every mutation goes through `lib/audit.ts`** — `mutateWithHistory()` writes the row, the revision
  and the audit entry in ONE transaction. A log that can exist without its change is a log nobody can
  trust during an incident.
- **Read paths filter soft deletes.** Use `livePublishableWhere()` (models with publishAt/unpublishAt)
  or `liveStatusWhere()` (models with only `status`) from `lib/content.ts`. They are separate
  functions on purpose: referencing a column a model does not have is a runtime error.
- **Publication state is resolved at READ time.** The cron is a convenience so the studio's status
  column matches reality; the filters are the mechanism.
- **Server Components read the database directly** through `lib/db.ts`. Only interactive studio
  screens fetch over HTTP, through `lib/client/fetcher.ts`.
- **List pages guard their fetch races.** A generation counter for lists (ignore the late answer), a
  `cancelled` flag for one-shot effects, an `AbortSignal` where the fetch accepts one.
- **`items === null` vs `items === []` is a deliberate distinction**: null renders "Loading…", `[]`
  renders the empty state. "No publications" during a fetch is both wrong and discouraging.

## 10. Forms

- Studio forms are **controlled React state** (they autosave and need dirty tracking), unlike the
  upstream field forms. Public forms (contact, registration) are uncontrolled `FormData`.
- ⚠ In any uncontrolled form, **`new FormData(event.currentTarget)` MUST be the first statement of
  the submit handler, before any `await`.** React nulls `event.currentTarget` across an await.
- **A `<label>` forwards a stray click to the first labelable control inside it**, so a `<label>`
  wrapping a dropdown slams the menu shut after one pick, and it folds every named descendant into
  the input's accessible name. → **Use `<Field>` (a `<label>`) for plain inputs and `<FieldBlock>`
  (a `<div>` + `htmlFor`) for anything containing a button.**
- **Themed dropdowns are `<button>`s and fire no native input event**, so an `onInput` dirty-tracker
  never sees them. Every custom control must call `onDirty` by hand.
- **A field may only be mandatory where it is answerable.** A required closed list with no options
  (because the fetch failed) blocks a submit with no way forward — stand the requirement down.
- Autosave every few seconds; confirm before deleting; soft-delete with a recycle bin; validate
  required fields; inline help on every field; character counters on titles and summaries.

## 11. Accessibility contract

- Every interactive element is a real `<button type="button">` or `<Link>`. Tab order is DOM order.
- One `<h1>` per page. Heading levels never skip.
- Every image from the media library renders `alt` — `""` for decorative (meaningful in HTML: it
  tells a screen reader to skip), a real sentence otherwise. The studio nags for the real one.
- Dialogs: `role="dialog"` + `aria-modal` + a focus trap + Escape + focus restoration.
  **Danger-tone confirms focus Cancel, refuse a backdrop dismiss, and use `role="alertdialog"`** so
  no reflex click or Enter can delete anything.
- `aria-controls` only while the target is mounted — pointing at a missing id is worse than not
  pointing.
- Colour never carries meaning alone: every status has an icon and a word.
- The skip link is first in tab order: `sr-only … focus:not-sr-only focus:fixed` → `#main-content`.

## 13a. `loading.tsx` and the soft-404 — read before adding one

**A `loading.tsx` may only go in a segment with no `notFound()` call anywhere beneath it.**

A `loading.tsx` wraps its segment *and every segment beneath it* in a Suspense boundary. Next then
streams: it sends the fallback immediately, which **flushes the HTTP response headers, including the
status line, as `200 OK`**. A later `notFound()` renders the 404 UI into the body of a response whose
status is already committed. The reader sees a 404 page; every machine sees a success.

That is a soft-404, and it is damaging here specifically: search engines index the 404 page under the
dead URL, broken-link monitoring detects nothing because every URL "works", and a citation pointing at
a withdrawn publication appears to resolve.

This shipped once — a `loading.tsx` at the `(site)` group root meant every missing person, project,
publication, article, event, album and craft returned 200 with 404 content.

- The only `loading.tsx` under `app/(site)/` is `search/loading.tsx`. Its header carries the full
  explanation.
- Segments that call `notFound()` themselves include the feature-flag gates on `/events`, `/gallery`
  and `/craft-explorer` — a flag that gates a surface gates its pages too.
- **Instead**, put an explicit `<Suspense>` *inside* the page around the slow part only, and make the
  `notFound()` decision *before* it. The status is settled before streaming begins and the reader
  still gets a progressive page.

The same reasoning applies to any streaming boundary, not just `loading.tsx`: nothing may stream
before the status is decided.

## 13b. The client/server route contract

**A `fetch` path is a string. Nothing in TypeScript checks it against a route file.** A screen calling a
handler that does not exist typechecks, lints and builds cleanly, and fails only when somebody clicks —
as a 404, or as a **405** from a neighbouring dynamic route that swallowed the path. More than twenty
such call sites shipped here at once, including the relation picker used by every editor in the CMS.

- **`npm run route-check` is part of `npm run check`.** It resolves every `/api/...` literal in the
  source the way Next does and fails on any that has no handler exporting that method. Run it after
  adding or renaming a route on either side.
- **`npm run smoke` is what actually proves a handler works.** `route-check` only proves a path
  resolves; a route can exist, resolve, and 500 on every call. The smoke test signs in and asserts
  every screen and studio endpoint answers, that a refusal is **403 and not 500**, that an anonymous
  studio API call is **401 JSON and not an HTML login page**, and that a create→publish→delete
  lifecycle works end to end. Run it before every deploy — see the README's *verification suite*.
- **A static segment always beats a dynamic one.** That is what makes `news/categories/route.ts` fix a
  path currently being eaten by `news/[id]/route.ts` — and what makes the absence of the static file a
  405 rather than an honest 404.
- When client and server disagree, **the client is the specification** unless it is plainly wrong: the
  screen is what a person uses, and the route exists to serve it.

## 14. Trap index — check before you "simplify"

- `rounded-2xl` == `rounded-lg` (16px); `rounded` is 4px, tighter than `rounded-sm`.
- `font-serif` is Plus Jakarta Sans.
- `border` alone = literal gray-200; `ring-2` alone = stock **blue**.
- `cn()` is a plain join, not tailwind-merge — later classes do not win.
- The scroll lock is on `<html>`, not `<body>` (iOS Safari ignores it on the body).
- Fixed overlays must re-pay `var(--scroll-gutter, 0px)` themselves.
- There is no `[data-reduced-motion="false"]` rule — the two sources only union.
- Zeroing `transition-delay` alongside the duration is load-bearing (a delayed zero-duration
  transition is a staggered pop, not "no motion"). Express stagger as `transition-delay`, not a JS
  timer, wherever CSS can do the job.
- `suppressHydrationWarning` on `<html>` and the boot script go together; removing either breaks the
  other.
- The `.nav-sheet` doubled `max-height` (vh then dvh) is progressive enhancement, not a duplicate.
- A `loading.tsx` above any `notFound()` turns every 404 into a 200. See §13a.
- Zod's `.default()` fires for a MISSING key, never for an explicit `null` — passing `null` to a
  defaulted field is a validation failure, not a default.
- `Prisma.JsonNull`, never a bare `null`, when writing a nullable `Json` column.
- Prisma `Decimal` arrives over JSON as a **string** — nothing in this schema uses Decimal for
  exactly that reason; keep it that way.
- Media `url`/`objectKey` may be absent by entitlement — never assume a variant exists.
- `uploadMedia` reports partial failure: **inspect the failed list and name the files that did not
  make it**. Treating a resolved promise as success silently loses files.
- A dialog that is not dismissable still calls `preventDefault()`/`stopPropagation()` on Escape, so
  the key cannot reach a parent dialog.
- `EmptyState` renders its own heading — do not drop it into a section that already has one at the
  same level.
